Concepts#

A GeoRasterFrame#

A GeoRasterFrame is a DataFrame or GeoDataFrame in which one column holds a raster for each row. The rows are entities: people, parcels, sites, stations. The raster is an attribute of the entity, just like its age or its geometry. It is a data structure, like a DataFrame, not a file format and not a new class: a table is a GeoRasterFrame if it has a column of dtype raster.

import numpy as np, pandas as pd, tempfile, pathlib, rasterio
from rasterio.transform import from_origin
import entityraster as er

tmp = pathlib.Path(tempfile.mkdtemp())

def write(name, value, x0, y0):
    """A tiny 4x4 raster with 10 m cells whose upper-left corner is (x0, y0)."""
    with rasterio.open(tmp / name, "w", driver="GTiff", height=4, width=4, count=1, dtype="float32",
                       crs="EPSG:3067", transform=from_origin(x0, y0, 10, 10), nodata=-9999) as dst:
        dst.write(np.full((4, 4), value, dtype="float32"), 1)
    return str(tmp / name)

people = pd.DataFrame({"name": ["Anna", "Ben", "Cleo"],
                       "path": [write("anna.tif", 1, 0, 40), write("ben.tif", 2, 20, 40), write("cleo.tif", 3, 0, 20)]})
gdf = er.embed(people, path_col="path", column="raster")
gdf
name path raster raster_extent
0 Anna /var/folders/d5/hzj_s3dn4gj_pdr3911r_qc00000gn... <Raster 4×4 @10m> POLYGON ((40 0, 40 40, 0 40, 0 0, 40 0))
1 Ben /var/folders/d5/hzj_s3dn4gj_pdr3911r_qc00000gn... <Raster 4×4 @10m> POLYGON ((60 0, 60 40, 20 40, 20 0, 60 0))
2 Cleo /var/folders/d5/hzj_s3dn4gj_pdr3911r_qc00000gn... <Raster 4×4 @10m> POLYGON ((40 -20, 40 20, 0 20, 0 -20, 40 -20)) 
er.is_georasterframe(gdf), gdf.rst.raster_columns, gdf["raster"].dtype

(True, ['raster'], <entityraster.dtype.RasterDtype at 0x12b100a10>)

Note that type(gdf) is still a plain GeoDataFrame: we did not subclass it, so every pandas and GeoPandas operation keeps working.

References, not pixels#

The raster column stores a small reference to each raster: where the file is, which band, and its metadata (CRS, transform, size, data type, nodata). The pixels stay in the GeoTIFF. That has three consequences:

  • Building and printing a table with thousands of rasters is instant, and saving it (GeoParquet) writes only the table.

  • Pixels are read lazily, only when an operation needs them and only for the rows involved. The counter er.READS shows it:

er.READS.reset()
gdf["raster"].rst.bounds()                       # metadata only
print("pixel reads after metadata:", er.READS.total)
gdf[gdf["name"] != "Ben"]["raster"].rst.mean()    # reads the two remaining rasters
print("pixel reads after a reduction on 2 rows:", er.READS.total)

pixel reads after metadata: 0
pixel reads after a reduction on 2 rows: 2

  • The files must stay where they were when the table was built (the paths are stored as given).

Every raster has its own extent#

Rasters in a collection rarely cover the same area. Here Anna and Ben overlap partly and Cleo sits below Anna:

gdf["raster"].rst.bounds()
minx miny maxx maxy
0 0.0 0.0 40.0 40.0
1 20.0 0.0 60.0 40.0
2 0.0 -20.0 40.0 20.0

To combine them, entityraster puts them on a common grid. That is only meaningful if they share a coordinate system, a cell size and an origin; if they do not, it stops and tells you which rows differ instead of guessing (Alignment: rasters that do not line up).

Zero or unknown? The choice you have to make#

Take the cell in the top row, third column: Anna’s raster covers it (value 1), Ben’s covers it (value 2), Cleo’s does not reach it. What is the average exposure at that cell?

  • If Cleo was never there, her exposure is 0: the mean is (1 + 2 + 0) / 3 = 1.0.

  • If we simply have no information about Cleo there, she should be left out: the mean is (1 + 2) / 2 = 1.5.

Both are legitimate; they answer different questions, and the difference can be huge. Most scripts pick one silently (usually by filling empty cells with 0 or NaN). entityraster makes you say it, for every operation that combines several rasters:

zero = gdf["raster"].rst.surface("mean", outside="zero")
unknown = gdf["raster"].rst.surface("mean", outside="unknown")
print("outside='zero'   :", float(zero[0, 2]))
print("outside='unknown':", float(unknown[0, 2]))

outside='zero'   : 1.0
outside='unknown': 1.5

try:
    gdf["raster"].rst.surface("mean")
except TypeError as e:
    print(e)

mean_surface() requires an explicit outside='zero' or outside='unknown'. Cells outside an entity's raster extent are either zero (never visited) or unknown (unobserved); the two give different results and there is no safe default.

Rule of thumb

Use "zero" when an empty cell means nothing happened there (counts, time spent). Use "unknown" when an empty cell means not measured or not modelled there (a model that only covers each person’s home range, a map with cloud gaps).

For a single raster no choice is needed, because the cells outside it are simply not part of that raster. The nodata cells inside it are ignored by default (p.mean()); p.mean(nodata="zero") counts them as 0 if you want that.

Weights#

A raster’s values can act as weights. The exposure of a person to, say, green space is the green value of each cell weighted by how much that person uses the cell (Weighted analysis and land use).

Where the geometry comes from#

A table with no geometry that goes through entityraster.embed() gets the raster extent as its geometry. A table that already has a geometry keeps it, and gains a second geometry column with the raster extent, which you can switch to with geometry="raster" (Attaching rasters to a table: embed).
