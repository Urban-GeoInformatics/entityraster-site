Attaching rasters to a table: embed#

entityraster.embed() is the front door. It joins rasters to a table by key, never by position, tells you what did not match, and manages the geometry. It works with or without a geometry column.

Set up some example files#

import warnings, tempfile, pathlib
import numpy as np, pandas as pd, geopandas as gpd, rasterio
from rasterio.transform import from_origin
import entityraster as er

tmp = pathlib.Path(tempfile.mkdtemp())

def write(path, value, x0=0, y0=40):
    path.parent.mkdir(exist_ok=True, parents=True)
    with rasterio.open(path, "w", driver="GTiff", height=4, width=4, count=1, dtype="float32", crs="EPSG:3067",
                       transform=from_origin(x0, y0, 10, 10), nodata=-9999) as dst:
        dst.write(np.full((4, 4), value, dtype="float32"), 1)
    return str(path)

folder = tmp / "rasters"
for uid, value in [(10, 1.0), (20, 2.0), (30, 3.0)]:
    write(folder / f"p{uid:03d}.tif", value, x0=uid)          # p010.tif, p020.tif, p030.tif

people = pd.DataFrame({"uid": [20, 30, 10], "age": [30, 65, 70]})      # deliberately not in file order
people
uid age
0 20 30
1 30 65
2 10 70

Where the rasters come from#

Give one of the following. In every case the result keeps the table’s rows, order and index.

You have

Call

a file-name pattern with the id in it

er.embed(people, folder, on="uid", pattern="p{uid:03d}.tif")

a folder (or glob, or list of files) named after the id

er.embed(people, folder, on="uid", pattern=...) or, if the file stem is the id, simply on="uid"

a name template built from the row

er.embed(people, template="rasters/p{uid:03d}.tif")

a catalogue table: id and path

er.embed(people, catalogue) (the join key and the path column are inferred when only one choice is possible)

a dict or Series mapping id to path

er.embed(people, {10: "...", 20: "..."}, on="uid")

a path column already in the table

er.embed(people, path_col="path")

a list of paths in the same order as the rows

er.embed(people, paths, positional=True) (only if you are certain: matching by position is fragile)

 
a = er.embed(people, folder, on="uid", pattern="p{uid:03d}.tif")                # pattern
b = er.embed(people, template=str(folder) + "/p{uid:03d}.tif")                  # template
catalogue = pd.DataFrame({"uid": [10, 20, 30], "file": [str(folder / f"p{i:03d}.tif") for i in (10, 20, 30)]})
c = er.embed(people, catalogue)                                                 # catalogue, nothing else needed
d = er.embed(people, {10: str(folder / "p010.tif"), 20: str(folder / "p020.tif"), 30: str(folder / "p030.tif")}, on="uid")
[x["raster"].rst.mean().tolist() for x in (a, b, c, d)]                         # all identical: 2, 3, 1 (the table's order)

[[2.0, 3.0, 1.0], [2.0, 3.0, 1.0], [2.0, 3.0, 1.0], [2.0, 3.0, 1.0]]

The five options you will use most: on, pattern or template, column, index and geometry. Everything else has a safe default.

Naming the column and the index#

gdf = er.embed(people, folder, on="uid", pattern="p{uid:03d}.tif", column="activity_space", index="uid")
gdf.loc[20, "activity_space"].mean()

2.0

Geometry: what you get#

Your table

Result

has no geometry (a plain DataFrame)

a GeoDataFrame whose geometry is the raster extent

has a geometry (points, polygons, anything)

the original geometry stays the default; the raster extent is added as a second geometry column, raster_extent

either of the above with geometry="raster"

the raster extent becomes the default geometry; the original column is kept

 
plain = er.embed(people, folder, on="uid", pattern="p{uid:03d}.tif")
print("plain table  ->", type(plain).__name__, "| default geometry:", plain.geometry.name)

homes = gpd.GeoDataFrame(people, geometry=gpd.points_from_xy([5, 25, 45], [5, 25, 45]), crs=3067)
both = er.embed(homes, folder, on="uid", pattern="p{uid:03d}.tif")
print("with points  ->", both.geometry.name, "(kept) +", [c for c in both.columns if "extent" in c], "(added)")

swapped = er.embed(homes, folder, on="uid", pattern="p{uid:03d}.tif", geometry="raster")
print("geometry='raster' ->", swapped.geometry.name, "| original still there:", "geometry" in swapped.columns)

plain table  -> GeoDataFrame | default geometry: raster_extent
with points  -> geometry (kept) + ['raster_extent'] (added)
geometry='raster' -> raster_extent | original still there: True

The extent is the raster’s bounding box by default (cheap: only headers are read). To use the real shape of the valid cells, or their convex hull (for example a modelled home range), pass extent="valid" or extent="hull"; these read the pixels once.

hull = er.embed(homes, folder, on="uid", pattern="p{uid:03d}.tif", extent="hull", geometry="raster")
hull.geometry.area.tolist()

[1600.0, 1600.0, 1600.0]

When something does not match#

Rows without a raster, files without a row, duplicate keys and unreadable files are reported, never silently dropped:

partial = {10: str(folder / "p010.tif"), 30: str(folder / "p030.tif"), 99: str(folder / "p010.tif")}   # 20 missing, 99 unused
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    out = er.embed(people, partial, on="uid")
print(str(caught[0].message))
out.attrs["embed_report"]

embed: 1 of 3 rows have no raster (e.g. [0]), 1 raster(s) matched no row (e.g. [99])

{'n_rows': 3, 'unmatched_rows': [0], 'orphan_rasters': [99], 'n_unreadable': 0}

out["raster"].isna().tolist()          # the row without a raster is an ordinary missing value

[True, False, False]

Options for control: how="inner" drops rows without a raster; strict=True turns the problem into an error; warn=False silences the warning (the report is still there); duplicates="first" or "last" resolves repeated keys (the default "error" refuses to guess).

(folder / "p020.tif").rename(folder / "moved.tif")                          # simulate a missing file
try:
    er.embed(people, folder, on="uid", pattern="p{uid:03d}.tif", errors="raise")
except FileNotFoundError as e:
    print(e)

    warnings.simplefilter("ignore")
    coerced = er.embed(people, template=str(folder) + "/p{uid:03d}.tif", errors="coerce")

Mixed coordinate systems#

If the rasters use different CRS and the table has no geometry to say which one to use, embed asks for crs= for the extent geometry; with a geometry column the extent is converted to the table’s CRS.

Recipes#

# a survey and a folder of files named after the person id (the most common case)
gdf = er.embed(survey, "rasters/", on="uid", pattern="p{uid:05d}.tif", column="activity_space", index="uid")

# the paths are already in the survey export
gdf = er.embed(survey, path_col="raster_file", column="activity_space")

# a catalogue that lists id and path
gdf = er.embed(survey, catalogue, column="activity_space")

# keep your point geometry, add the modelled home range as a second geometry
gdf = er.embed(survey_points, "rasters/", on="uid", pattern="p{uid:05d}.tif", extent="hull")
