Extending: backends and generators#

A raster reference names a backend, which knows how to read its metadata and pixels. Two are built in: geotiff (files read with rasterio) and derived (rasters computed by a function). You can add your own, for example Zarr, a cloud-optimised GeoTIFF over HTTP, or an in-memory array.

A custom backend#

A backend is any object with a name, a metadata(href, band, params) method returning the header dictionary, and a read(ref, window) method returning a masked array:

import numpy as np
import entityraster as er
# READS is the pixel-read counter; a backend should record each read in it
from entityraster.backends import READS

class InMemory:
    """Rasters held in a dictionary (a stand-in for a database, Zarr store or web service)."""
    name = "mem"
    # two tiny 4x4 rasters, looked up by their href
    store = {"a": np.arange(16, dtype="float32").reshape(4, 4), "b": np.ones((4, 4), dtype="float32")}

    def metadata(self, href, band=1, params=None):
        # header only: grid geometry and type, no pixels are needed here
        h, w = self.store[href].shape
        return dict(crs="EPSG:3067", transform=(10.0, 0, 0, 0, -10.0, 10.0 * h), width=w, height=h, dtype="float32", nodata=None)

    def read(self, ref, window=None):
        READS.record_read(ref.href)           # count the read so tools can verify what was touched
        # no window means the full array; otherwise cut out the requested rows and columns
        a = self.store[ref.href] if window is None else self.store[ref.href][window.row_off:window.row_off + window.height,
                                                                              window.col_off:window.col_off + window.width]
        return np.ma.masked_array(a)          # readers return masked arrays (nothing masked here)

# make the backend available under its name, "mem"
er.register_backend(InMemory())
# a raster column whose references point at the backend; the table itself holds no pixels
col = er.raster_series([er.RasterRef("a", backend="mem"), er.RasterRef("b", backend="mem")])
# per-raster means and bounds work exactly as for GeoTIFF-backed columns
col.rst.mean().tolist(), col.rst.bounds().iloc[0].tolist()

([7.5, 1.0], [0.0, 0.0, 40.0, 40.0])

Everything else works unchanged on such a column: reductions, surfaces, embed, GeoParquet.

# mean surface across the two rasters; "zero" says cells outside a raster count as 0
col.rst.surface("mean", outside="zero").shape

(4, 4)

A computed raster (generator)#

A generator is a function f(grid, **parameters) that returns the array. A reference built with make_ref() stores the function name and the parameters, so the raster is lazy (computed when read, cached) and carries its provenance:

# register the function under a name; references store this name and the parameters, not the pixels
@er.register_generator("ramp")
def ramp(grid, slope):
    return np.arange(grid.width * grid.height, dtype="float32").reshape(grid.shape) * slope

# the grid the raster lives on: CRS, affine transform, width, height
grid = er.Grid("EPSG:3067", (10.0, 0, 0, 0, -10.0, 40.0), 4, 4)
# lazy reference: nothing is computed yet
ref = er.DerivedBackend.make_ref("ramp", grid, {"slope": 0.5})
er.READS.reset()                             # start the counters from zero
print("before reading, materializations:", er.READS.materializations, "| shape known:", ref.shape)
# the mean forces the computation, so materializations goes up by one
print("mean:", ref.mean(), "| materializations after:", er.READS.materializations)
ref.params                                   # the stored provenance: the parameters used

before reading, materializations: 0 | shape known: (4, 4)
mean: 3.75 | materializations after: 1

'{"dtype": "float32", "func": "ramp", "grid": {"crs": "EPSG:3067", "height": 4, "transform": [10.0, 0, 0, 0, -10.0, 40.0], "width": 4}, "kwargs": {"slope": 0.5}, "nodata": null}'

The IREM-style activity spaces used in the examples are produced this way (entityraster.irem).

The pixel-read counter#

er.READS counts pixel reads (total, by_href), derived-raster computations (materializations) and header reads (metadata_calls). The test suite uses it to prove that building a table and reading metadata read no pixels, and that a filter followed by a statistic reads exactly the selected rows. You can use it the same way to check your own workflow.
